## Feedback

In a CLI with several subcommands, the arguments are one `&mut RawArgs` shared across the subcommands, and each subcommand is tried in turn.

`finish(self)` can only be called once, at the end, because it consumes `self`. Calling it inside a subcommand's handling means the later `finish` has nothing to receive, so `finish` ends up only ever being placed after every side effect has already run.

As a result, a stray argument is reported after the work is done. `tool create NAME EXTRA` reports `EXTRA` as unconsumed, but only after the file for `NAME` has been written, and then exits 1. Commands that move files behave the same way: a mistyped command line changes the file system before it fails. The error for a missing required subcommand, when not in help mode, is reported at the same late point.

What is confusing is that the command line was wrong the whole time, yet the change happened first.

## Outcome

Accepted. The report is accurate for the case that matters: because
`finish(self)` consumes `self`, `finish` can only sit after every side effect,
so a stray argument is reported once the work is done.

One part of the report is not quite the shape of the code, and it does not
change the decision. Only the stray-argument check is confined to `finish`.
A missing required subcommand is checked by `Error::check_command_error`, which
`finish` calls but which is also reachable from `Cmd::is_present` -- a command
that checks whether its subcommand is present gets that error at the `take`,
not at the end. So the two errors the report groups together are fixed at
different points; the late side effect is the stray argument, which is the
case the report leads with.

The decision is carried by `rfc-subcommand-arg-handling`, which hands
`RawArgs` to the subcommand handler by value so that `finish` is called
inside the handler, after every `take` and before any work. The library keeps
`finish(self)`: the freedom to call `finish` and then `take` again is not
wanted yet, and narrowing that later is not possible while widening it later
is. The RFC is open until that change to `examples/subcommands.rs` lands, so
this item is closed ahead of the work it names.
